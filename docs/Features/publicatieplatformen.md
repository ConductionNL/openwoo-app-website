# Keuze uit publicatieplatformen

OpenWoo legt geen frontend op. Je organisatie kiest welk publicatieplatform het beste past — als losse zoekpagina, geïntegreerd in de huidige website, of in een specifiek CMS.

## Wat het doet

OpenWoo is in essentie een API-koppelvlak. Bovenop die API kan elke organisatie of leverancier een eigen weergave bouwen. Dat geeft je organisatie de vrijheid om bij je huidige look-and-feel te blijven, in plaats van een tweede subdomein met een afwijkende huisstijl te accepteren.

## De huidige opties

| Frontend                       | Leverancier(s)        | Geschikt voor                                  |
|--------------------------------|-----------------------|------------------------------------------------|
| OpenCatalogi zoek-UI           | Conduction            | Losse NL Design-zoekpagina in je huisstijl     |
| OpenWoo default zoek-UI        | Conduction, Shift2    | Losse NL Design-zoekpagina                     |
| Tilburgse frontend             | Acato                 | Losse NL Design-zoekpagina (productie­bewezen) |
| Integratie in Open Webconcept  | Yard, Conduction      | WordPress-websites                             |
| Drupal-site                    | Drupal voor Overheden | Drupal-websites                                |
| TYPO3-themasite                | OpenGemeenten         | TYPO3-websites                                 |

## Waarom dat ertoe doet

De gemeente Gouda gebruikt een andere websitestack dan de gemeente Tilburg. Een Woo-oplossing die alléén een eigen frontend levert, dwingt elke gemeente in dezelfde mal — of, erger nog, in een tweede afwijkend domein. Door frontend-keuze als eigen as in de architectuur op te nemen, sluit OpenWoo aan op wat er al draait.

Zie [Publicatieplatform — Architectuur](../Architecture/publicatieplatform.md) voor de volledige codebase-overzicht.
